# Notch: общая концепция

## Одной фразой

Ноутбук — не журнал экспериментов, а исполняемый список задач. Ячейка одновременно код,
задача и запись в туду. Один файл — источник правды для человека, для агента и для деплоя.

## Почему ячейка

У ячейки уже есть три свойства, которых нет у обычной задачи в трекере:

1. **Она исполняема.** Задача не описывает работу, а делает её.
2. **У неё есть входы и выходы.** В реактивном ноутбуке (marimo) зависимости между
   ячейками выводятся из кода. Значит, зависимости между задачами не надо проставлять
   руками — они уже есть.
3. **Она видна целиком.** Код, результат, комментарий и статус в одном месте, а не в трёх
   системах.

Обычный ноутбук (Jupyter) этого не даёт: порядок выполнения произвольный, состояние
скрытое, «что устарело» неизвестно. Поэтому основа — реактивный.

## Три вида задач

| Вид | Кто делает | Что происходит |
| --- | --- | --- |
| Локальная | агент прямо в ноутбуке | выполняет функцию, пишет файл, запускает команду; результат остаётся в ячейке |
| Предложение | агент предлагает, человек подтверждает | уходит в хаб, ждёт подтверждения по passkey, только потом действует наружу |
| Заметка | человек | ничего не исполняет, держит контекст рядом с кодом |

Граница между первым и вторым — граница внешнего эффекта. Всё, что меняет мир за пределами
ноутбука, проходит через подтверждение собой. Всё, что не выходит наружу, агент делает сам.

## Где живёт список задач

В хабе, не в файле. Причины:

- код ноутбука монтируется только на чтение, писать в него нельзя по замыслу;
- в хабе уже лежат события и подтверждения книги — задачи становятся частью того же потока,
  а не четвёртым отдельным списком;
- агенты, доска в ноутбуке и телефон видят одно и то же состояние.

Локально держится только черновик — задача, которая ещё не стала предложением.

## Куда это растёт

- **Единый источник правды.** Один файл описывает, что сделано, что предложено и что
  разворачивается. Не документация рядом с кодом, а сам код как документация.
- **Деплой как задача.** Развернуть сервис — такое же предложение с подтверждением, как
  и всё остальное. История деплоев = история подтверждённых задач.
- **Совместная работа.** Несколько людей со своими агентами работают в одном списке:
  агент предлагает, человек подтверждает, все видят результат.

## Чего сознательно не делаем

- Не заводим свой трекер задач параллельно хабу.
- Не даём агенту действовать наружу без подтверждения.
- Не храним состояние в файлах ноутбука — оно расходится между копиями.
